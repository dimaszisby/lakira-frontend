## 6. New findings

### N1 · API Contract (P1) — the proxy forwards outside its API base

**Status:** PARTIAL · **Effort:** S
**What's wrong:** `src/app/api/proxy/[...path]/route.ts:56-58` joins the route's path segments
into a URL under the API base and lets `new URL()` normalise it. A segment that decodes to
`../../health` climbs out of `/api/v1`. The token check at `:71` tests only that a cookie is
present, so any cookie value is enough.
**Reproduced:** `GET /api/proxy/..%2f..%2fhealth` with `Cookie: lakira_token=x` returned the
backend's own `Cannot GET /health` 404, byte-identical to requesting `http://localhost:8001/health`
directly. `/api/v1/health` returns 200, so the request was served from the origin root.
**Why it matters:** the proxy is the one hop that defines what the browser can reach. Today the
paired backend mounts nothing outside `/api/v1` that was found (`/health`, `/api-docs` and
`/metrics` are all 404), which is why this is P1 and not P0. A fork whose backend shares an origin
with a docs UI, a metrics endpoint or another service exposes it through the frontend, with the
caller's bearer token attached.
**Fix:** reject any segment containing `/`, `\`, or equal to `.` or `..`; then assert the built
URL's pathname still starts with the base pathname. Add both as unit tests: the 14 tests in
`route.test.ts` cover no traversal case.
**Evidence:** `route.ts:56-58`, `:71`; section 2.2.

### N2 · Forkability (P1) — a bootstrapped fork fails the `format` gate

**Status:** PARTIAL · **Effort:** S
**What's wrong:** `scripts/bootstrap-fork.sh` rewrites the brand inside Markdown tables. The new
name has a different length, so the table padding no longer matches what Prettier writes.
`prettier --check .` then fails on five files: `docs/how-to/development/run-against-a-local-backend.md`,
`docs/how-to/development/sync-the-openapi-spec.md`, `docs/reference/commands.md`,
`docs/reference/configuration.md` and `docs/reference/environments.md`.
**Why it matters:** `format` is the last step of CI's `checks` job, and every later job depends on
it. A fork's first push is red, and the script's own "reinstall and verify" list
(`scripts/bootstrap-fork.sh`, step 3) does not include `format`, so the forker is not told. The
backend's 2026-10-03 run found the same class of defect in its bootstrap (its S2).
**Fix:** run `prettier --write` over the rewritten files at the end of the script, and add
`npm run format` to the printed verification line. Then re-run the fork test.
**Evidence:** section 2.3. This has been true since `format` became a gate on 2026-09-20.

### N3 · Auth (P1) — the access token passes through browser JavaScript at sign-in

**Status:** PARTIAL · **Effort:** M
**What's wrong:** login, register and switch-organization call the backend through the proxy from
the browser. The response body carries the access token, the mutation reads it
(`src/features/auth/hooks/login.mutation.ts:23-24`,
`src/features/organizations/hooks/switch-organization.mutation.ts`) and posts it to
`/api/auth/session`, which sets the httpOnly cookie. For that moment the token is a JavaScript
value. `.claude/rules/security.md:32` states "The token never touches JavaScript".
**Why it matters:** the httpOnly cookie exists so that injected script cannot read the session.
Script running on the login page can read it from the response instead, and N4 means the CSP does
not stop inline script. The baseline graded this Pass when a server-side login route held the
token; that route was removed on 2026-09-13 (`e54e607`), and the rule was not revisited.
**Fix:** have the server set the cookie. Either a route handler per sign-in operation, or the proxy
strips `token` from those three responses and writes the cookie itself. Then `/api/auth/session`
`POST` can go, which also removes the route that fails open when the backend is unreachable.
**Evidence:** as cited; `src/features/shared/session.client.ts:10-19`.

### N4 · Security (P2) — the production CSP allows inline script

**Status:** PARTIAL · **Effort:** M
`next.config.ts:17` sets `script-src 'self' 'unsafe-inline'` in production, confirmed on the live
response. With it the CSP does not block an injected inline script, which is the main thing a CSP
is for. `.claude/rules/security.md` records that `unsafe-eval` is development-only and says nothing
about `unsafe-inline`. **Fix:** a per-request nonce, which Next supports from `src/proxy.ts`, or
record the deviation and its reason where the CSP is documented.
