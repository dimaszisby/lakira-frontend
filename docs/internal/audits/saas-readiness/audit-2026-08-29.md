## 1. Verdict

**FORK-READY WITH CAVEATS.** All four ADR-001 criteria now pass: zero P0 gaps, all ten
empirical gates green, every critical category at or above 80%, and `LICENSE` + `.env.example`
present at the root.

Seven remediation phases landed between 2026-08-24 and 2026-08-29. The changes that moved the
verdict, in rough order of weight:

- **Tenant isolation.** Five cache-key factories now carry the organization id, with 94 tests
  where there were none, and both guards proven to fail on regression rather than assumed. This
  was the finding that drove the baseline's NOT FORK-READY.
- **Auth is no longer broken by design.** The backend issues 15-minute tokens into what was a
  7-day cookie, so sessions died a quarter of an hour after login. Refresh-on-401 fixes that,
  and the four missing account-lifecycle flows are built.
- **The proxy denies by default**, against an allowlist derived from the OpenAPI contract
  rather than guessed. `analytics/*` and `admin/_ping` were previously proxied unauthenticated.
- **Env, observability and forkability scaffolding** all exist where they did not.
- **The vacuous gates are real.** Coverage thresholds went from 3/2/3/3 to numbers that fail
  when coverage drops, and `coverage:check` runs in CI.

What holds it short of a clean verdict is a cluster of six caveats (C1–C6 below), of which the
two that matter are: **the organization switcher cannot be built** against the current backend
contract, and **three flows are implemented but unverified** because their tokens arrive by
email and this session cannot read the backend's stdout.

**Severity counts:** P0 = **0** (was 8) · P1 = **6** (was 21) · P2 = **9** (was 8).

it from this repo without choosing a host themselves. That is a real gap and it is why the
verdict carries caveats.

### Two baseline findings were withdrawn, not fixed

- **"`login/route.ts` bypasses the proxy."** It does not. The proxy exists so the _browser_
  never reaches the backend; that route is already server-side, so calling the backend is what
  the proxy itself does. Routing it through would make the server call itself.
- **"Integration tests are not MSW-backed; they mock feature hooks at module level."** False.
  12 of 17 suites use `server.use()` with real HTTP mocking; the rest are layout components
  making no network calls. **Zero** mock a feature hook. The empty global `handlers.ts` is
  correct design and stricter than a shared list. This claim originated in `CLAUDE.md` and
  propagated into the baseline audit — repeated, not verified.

## 6. Open caveats

Six, none blocking the ADR-001 gate.

### C1 · Multi-Tenancy (P1) — the organization switcher cannot be built

`/auth/switch-org` requires an `organizationId`, and no endpoint tells a client which
organizations the caller belongs to. There is no `GET /organizations`, and the `User` schema
carries no memberships — verified in the contract and against a live `/auth/profile`.

A multi-org user is stuck in whichever organization their token names. Backend handoff written.
**This is the single largest remaining gap in the SaaS surface.**

### C2 · Verification (P1) — three flows built but unverified

`verify-email`, `reset-password`, and the two-org in-session switch. The first two consume
single-use tokens delivered by email; the third needs the invite flow, which does the same. The
backend logs mail to stdout (`EMAIL_PROVIDER=console`), but its commit `47854e2` moved logging
off disk and the server runs outside this session.

What _was_ verified: both endpoints reject invalid tokens cleanly; `forgot-password` returns
byte-identical responses for real and non-existent addresses (no enumeration oracle); two
distinct organizations return 403 cross-org in both directions through the frontend proxy.

Not verified: the success paths, and one user switching organizations in a live session — the
scenario the cache-key work exists for.

### C3 · Observability (P1) — no vendor error sink

Structured JSON to stdout with `setLogSink()` as the seam. Collectable by any log drain, but
not an error aggregator. Needs a provider decision, a DSN, and a CSP ingest origin.

### C4 · CI/CD (P1) — no deploy job or deployment config

No `Dockerfile`, `vercel.json`, or deploy job. Deployment is Vercel-by-convention, inferred
from `VERCEL_URL` reads. The one thing keeping Category 8 below 80%.

### C5 · Security (P2) — `gitleaks-action` pinned to `v1.6.0`

A very old major, and it is the job standing between the repo and a leaked secret in public
history. Move to `gitleaks/gitleaks-action@v2`, SHA-pinned.

### C6 · Architecture (P2) — six files still quarantined from the layer rule

`withAuth.tsx`, `Header.tsx`, `Sidebar.tsx`, `HydrateUser.tsx`, `CategorySelect.tsx`,
`Visualization.tsx`. Unchanged since the baseline. Note `HydrateUser.tsx` is **dead code** —
imported by nothing — and `withAuth.tsx` reads a hand-written `["userProfile"]` cache key that
exists in no factory.

## 7. Smaller items, recorded not fixed

- `vizKeys.dashboard` has **no invalidator** — and it is the only SSR-prefetched key. Dashboard
  data is never invalidated by any mutation.
- `UserAtom` declares `token?: string`. Never populated, so dead rather than leaking, but
  `.claude/rules/security.md` says the token must never reach a global.
- `src/app/providers.tsx` nests `QueryClientProvider` **twice** with the same client, and
  accepts a `dehydratedState` prop that nothing uses.
- The backend returns a `stack` field with absolute file paths in error responses. Seen in
  development; confirm it is suppressed in production.
- One Cypress spec. E2E covers the public home page only.
- `npm run format` is red on ~110 files and runs in no CI job.
- 37 lint warnings, 0 errors. Down from 43 at baseline despite seven phases of new code.
