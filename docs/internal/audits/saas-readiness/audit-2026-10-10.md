## 6. New findings

All P2. None is a regression since 2026-10-04.

### N7, what is left — Next prints the raw error to stdout

The probe's Server Component threw with an email address, a `token=` query value and a bearer value
in its message. The application's line was scrubbed. The line before it was not:

```
⨯ Error: audit probe failed for jane.doe@example.com at /reset?token=abc123secret with Bearer abcdef0123456789abcdef
```

That line is written by Next, not by `src/lib/logger.ts`, so the scrub in the logger never sees it.
Neither ADR-0027 nor the `telemetry-log-hardening` kit mentions it. A log drain receives both lines.

### N12 — four forms print the transport error, not the server's message

`LogForm.tsx:135`, `MetricForm.tsx:165`, `MetricSettingsForm.tsx:172` and
`MetricCategoryForm.tsx:129` render the mutation error's `.message`. `withApiErrorHandling`
rethrows the original Axios error, whose message is "Request failed with status code 409"; the
server's own message is on the response and `handleApiError` would read it. Reproduced in a browser
on 2026-10-09: a second value logged in the same minute showed the Axios text, where the backend
had answered "A log entry already exists for this timestamp for this metric". The sign-in forms and
the organization switcher do normalize. Lowers one item (kit D-07).

### N13 — one unit test depends on the caller's environment

`src/lib/__tests__/csp.test.ts:127-136` compares the static policy from `next.config.ts`, which
reads `process.env.NEXT_PUBLIC_API_BASE_URL` (`next.config.ts:5-6`), with a policy built with an
empty API origin (`csp.test.ts:21`). With the variable exported the test fails; without it, it
passes. CI does not export it, so the gate is green there. A developer who exports the variable, or
a CI job that one day sets it at job level, gets a red unit gate for a reason unrelated to the
change.

### N14 — the development-only audit has grown, and one advisory is critical

### N15 — a second value in the same minute is refused

`toISOZ` rounds the logged time to the minute (`src/utils/date-io.ts:73-79`), and the backend keeps
one log per timestamp per metric and answers 409. A user who logs two values within a minute loses
the second, with the message N12 describes. Whether the form or the backend should change is a
product decision. Seen on 2026-10-09; the journey spec works around it by choosing another minute.
