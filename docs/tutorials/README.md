# Tutorials

Learning-oriented. Follow one start to finish; every command is meant to be pasted as-is.

| #   | Tutorial                                                  | You end up with                                                       |
| --- | --------------------------------------------------------- | --------------------------------------------------------------------- |
| 1   | [Getting started](./getting-started.md)                   | The app running locally, logged in, against a real backend            |
| 2   | [Your first feature slice](./your-first-feature-slice.md) | A feature module fetching and rendering data through the proxy        |
| 3   | [Your first component](./your-first-component.md)         | A token-driven UI primitive with passing unit and accessibility tests |

> Writing one? A tutorial teaches by doing and accepts no detours: no options, no alternatives, no
> explanation of _why_. Those belong in [`../how-to/`](../how-to/) and
> [`../explanation/`](../explanation/) respectively. If a step can fail for an interesting reason,
> say what the failure looks like rather than how to avoid it.
