# Design tokens

Six CSS layers, imported in a load-bearing order by `src/styles/globals.css`, with Tailwind 3
mapping the semantic variables into utilities via `tailwind.config.mjs`.

For the palette values and type scale as tables, see [`style/`](./style/). For the rules on how to
consume tokens in a component, see
[`../../.claude/rules/styling.md`](../../.claude/rules/styling.md).

## The six layers, in import order

The order in `globals.css` is not cosmetic — each layer consumes variables defined by the one above
it, so reordering breaks resolution silently (the variable resolves to nothing and the property is
dropped).

| #   | File                               | Holds                                                                      |
| --- | ---------------------------------- | -------------------------------------------------------------------------- |
| 1   | `tokens/palette.css`               | Raw brand colours. No UI meaning.                                          |
| 2   | `tokens/semantic.css`              | Surfaces, `--text*`, borders, `--ring`, interaction states, status triads. |
| 3   | `tokens/scales.css`                | Space, radius, elevation, z-index, control sizes, focus, motion, icons.    |
| 4   | `tokens/typography.css`            | Font smoothing, element defaults, `.text-body1` / `.text-caption` classes. |
| 5   | `tokens/components/<x>.tokens.css` | Variant → palette mapping, in `@layer base`.                               |
| 6   | `tokens/components/<x>.recipe.css` | `.x` plus `[data-variant]` / `[data-size]`, in `@layer components`.        |

Then `@tailwind base; @tailwind components; @tailwind utilities;`.

### Layer 1 — palette

Colours are stored as **bare HSL bodies**, not wrapped in `hsl()`:

```css
--primary-sakurapink-500: 351 64% 75%;
```

That is what lets Tailwind and downstream layers compose them with an alpha channel
(`hsl(var(--token) / 0.5)`). Wrapping the value in `hsl()` at definition time breaks every such
use, and the failure is silent.

### Layer 2 — semantic

Where theming happens. Both themes are defined explicitly:

```css
:root,
:root[data-theme="light"] { … }

:root[data-theme="dark"] { … }
```

Nothing below this layer should reference a palette variable directly. Layer 5 is the one exception
— it exists precisely to map a component's variants onto palette entries.

### Layers 5 and 6 — the two-file component pattern

A component that needs its own tokens gets **two** files, never one:

- `<x>.tokens.css` — declares `--button-primary-bg` and friends in `@layer base`, mapping variants
  to palette or semantic values.
- `<x>.recipe.css` — declares `.button` and its `[data-variant]` / `[data-size]` selectors in
  `@layer components`, consuming only the variables from the tokens file.

Every primitive in `src/components/ui` styles through a pair like this; shared looks share a recipe
(`input`, `popover`, `feedback`). The full contract — what may live in TSX and what may not — and
the lint rules that enforce it are in [`../../.claude/rules/styling.md`](../../.claude/rules/styling.md)
and [ADR-0016](../explanation/decisions/adr-0016-ui-primitives-conventions-ariakit-and-centralised-styling.md).

Tailwind's `theme.colors` is **replaced**, not extended, so only token colours generate utilities:
`bg-white` or `text-gray-400` produce no CSS.

## Theming

Theme is driven by a `data-theme` attribute on `<html>`, set by `next-themes` and the inline
`src/app/ThemeScript.tsx` (which runs before paint to avoid a flash).

Tailwind is configured to match:

```js
darkMode: ["class", '[data-theme="dark"]'],
```

**A bare `.dark` class does nothing.** Only `[data-theme="dark"]` switches the theme. This catches
people out because `.dark` is the Tailwind default and works in most other projects.

## Class merging

Merge with `cn()` from `src/lib/cn.ts` (clsx + tailwind-merge). Never concatenate class strings by
hand — `tailwind-merge` is what resolves conflicting utilities, and string concatenation defeats it.
`cn()` is configured with the named font-size scale, so `text-caption` and a text colour class are
not treated as conflicts.

## Fonts

Quicksand (`font-display`) and Plus Jakarta Sans (`font-ui`), loaded via `next/font/google` in
`src/app/layout.tsx`. The named size scale (`text-h1`…`text-h6`, `body1`, `body2`, `caption`, `btn`,
`nav`, `badge`) is defined in `tailwind.config.mjs`.

## Known defects

These are real and currently unfixed. They are recorded here so nobody rediscovers them:

- **The spacing scale is not wired to Tailwind.** `--space-1..7` exist, but `tailwind.config.mjs`
  has no `spacing` key, so `p-4` is Tailwind's default `1rem`. Values match for 1–6; mapping `7`
  would change every `*-7` utility app-wide.
- **Button colour tokens fail WCAG AA in light mode** (primary and secondary 1.96:1). Changing them
  is a brand decision.
- **`src/styles/output.css` is a stale build artifact.** It is generated by `npm run build:css`, is
  Prettier-ignored, and is not part of the token system.
